# 《邻里互助》需求文档

## 1. Overview

《邻里互助》是一款异步多人共享世界的文字角色扮演实验。玩家是普通公寓社区居民，在共享大厅、包裹架、楼梯间、街角店、小花园和住户门口处理取包裹、借还雨伞、送药、照看宠物、归还钥匙等日常小事。世界地域保持中性，不默认中国、美国或其他单一国家。

- 单次体验：5–12 分钟，完成或交接一件小事后可以自然离开，没有硬性结算页。
- 跨次连续性：共享委托和公共物品由所有玩家共同改变；个人关系、个人故事和私人物品归各自存档。
- 持久状态：个人精力、耐心、熟悉度、已认识人物、私人关系、个人收据；共享委托、公共物品归属、世界事件版本和公开互助记录。
- 回访理由：查看委托是否被别人完成或交接，继续一段居民关系，处理尚未确认的物品收据。
- 承诺层级：首个动作、首局、前 10 分钟、单次自然停止和长期共享世界均存在；没有强制通关承诺。

一句话核心玩法：从实时有效的邻里委托中选择一件事，与其他玩家错时协作，并让每次行动同时留下可信的公共结果和连续的私人故事。

首次价值时刻是一段无惩罚练习：玩家领取“把共享大厅最后一把雨伞送给公交站旁等待的邻居”，系统立即显示委托被领取、雨伞归属改变以及公告板状态更新。此后玩家应能回答：目标是完成一件邻里委托；反复做的是领取、携带、交接或完成；公告板和物品归属发生改变算进展，物品已被别人拿走或当前条件不满足时会失败并得到可恢复的解释。新玩家理解度在真人测试前标记为 `comprehension unverified`。

## 2. Visual Design

视觉采用温暖、朴素的编辑插画：暖纸色背景、墨绿色结构线、砖红状态强调和柔和晚间光线。主界面像一本正在使用的社区记录册，但不仿真成复杂表格。顶部显示三项个人状态，中部是累积正文与场景图，底部是当前可执行选择；关系入口沿用笔记本式线性 SVG 图标。

场景图只画玩家真正所在地点或重要对话中的人物表情，不在图内生成招牌、对话框或任何可读文字。人物、建筑、服装、交通设施和公共空间不得默认成中国小区，也不得用英文世界等同美国郊区。公共公告板使用真实 UI 文本渲染，不能把委托文字烘焙进生成图。完整视觉规则见 `doc/visual.md`。

## 3. Game Mechanics

核心动词是查看、领取、携带、交接、归还、完成、询问和求助。基本循环为：读取当前公告板和场景 → 领取委托或公共物品 → 权威服务原子提交 → 显示明确结果 → 私人叙事引用已提交事件 → 继续或停止。

个人状态：精力 0–100，初始 78，单回合变化上限 18；耐心 0–100，初始 72，单回合变化上限 16；熟悉度 0–20，初始 1，单回合变化上限 3。精力或耐心降到 8 以下时不能承担新的费力委托，但仍可归还物品、交接任务、休息或求助。数值只由结构化命令进入权威 reducer，正文不得打印状态清单。

公共物品是具有稳定实例 ID 的唯一对象，例如最后一把备用雨伞、唯一备用钥匙或某个具体包裹。一个物品同一时刻只能处于公共位置、某玩家持有、交接中或已归还之一；收据待确认是个人存档同步状态，不进入公共物品状态机。布质钥匙袋一次只能保管一件公共物品。

共享委托状态为 `open → claimed → handed_off/completed`，必要时可 `cancelled`。领取、执行、交接和完成是不同权威阶段；一个按钮只能表达并提交一个阶段。例如开局只能“领取并拿起雨伞”，送到公交站必须是领取成功后出现的下一项动作。所有写入带 `action_id` 与 `expected_version`；重复提交只执行一次，旧版本选择返回明确冲突。发生竞争时，正文先解释“这把伞刚被另一位居民借走了”等可感知原因，再刷新选择；若原意仍可实现，恢复选择优先保留原意。

共享行动提交成功后，客户端只根据提交后的请求快照渲染确定性结果，再从最新权威状态建立选项。模型生成、校验、图片或网络后续步骤失败，都不能把已提交成功的行动写成失败，也不能恢复提交前的旧选项。`claimed` 正文不得描述完成或送达；`completed` 后不得再次出现领取、交接或完成同一委托的按钮。

权威服务生成物品收据；客户端把收据恰好一次合并进个人存档，保存并读回验证后才确认收据。公共互助次数可共享展示，人物好感、私密对白和个人故事不得进入共享事件流。重要对话只在公共行动提交成功后建立稳定事件 ID，并以该 ID 幂等生成一次表情场景图。

世界威胁只来自日常状况：电梯停运、入口积水、送药变急、宠物走失或一个物品同时被两个委托需要。开局前 6 个场景不安排随机压力事件；之后至少经过 3 个安全回合、最迟第 5 个安全回合触发，触发后冷却 2 回合。威胁必须与当前地图节点相容。没有物理战斗；玩家可求助、交接或改走更安全路线。

危险状态必须同时满足三项才可提交：正文明确写出当前威胁、结构化 `encounter` 使用同一阶段和威胁、所有系统选项都明确处理该威胁。红灯、封路或其他阻碍尚未解决时，不得切换到无关委托；只有可见正文解释同一威胁已经结束，并在同一回合提交 `resolution`，才能回到平静状态。生成或校验失败时，原动作进入隔离记录而不会再次作为按钮出现；危险线程直接保留只针对当前威胁的确认、应对和撤离选项，不经过通用恢复菜单。危险回合经过一次生成修复仍不合格时，本地状态机必须写出同一威胁的确定性短结果并推进当前阶段，不能依赖模型重试才能继续。

个人叙事层的普通推荐失败时，只移除失败动作，保留仍可信的同级选项；连续失败必须使集合严格缩小。没有可信同级选项时允许快捷栏为空并由自由输入继续，不得为了凑够两个或三个按钮再造通用观察、等待或换路选项。此隔离只修改个人故事存档，不回滚、伪造或重写已经由共享世界事务提交的委托、唯一物品、事件或回执。

## 4. Controls

- Pointer/Touch：点按公告板委托、底部选择、笔记本关系入口和返回按钮；所有触控目标至少 44×44 CSS px。
- Keyboard：数字键 1–5 选择当前可见选项，只有开场最后一个作者节拍后才启用；Tab 可遍历所有控件，Enter/Space 激活。
- Scroll：正文和公告列表用正常滚动，列表项使用 `onClick`，不得用 `onPointerDown` 抢占滑动。
- 自由输入：只在当前回合允许时出现，提交前保持可编辑，网络请求期间先给即时视觉反馈。可识别的领取、送达、交接和完成自然表达必须解析到与按钮相同的请求与权威事务；目标不明确时不得猜测某一委托，应保留状态并交回开放叙事。

## 5. Win / Lose Conditions

游戏没有总胜利、Game Over 或固定结局。完成或交接一件委托构成一次部分成功和自然停止点；玩家可以立即离开，下次从已提交的地点、委托和关系继续。

委托被别人先领取、物品不可用、版本过期、精力不足或地点不匹配均是可恢复失败，不删除存档。系统必须保留已完成事实，解释冲突并给出新的有效行动。网络中断时保留稳定 `action_id` 供同 ID 重试；不能把一次点击变成两次公共结果。

已保存于旧版危险恢复循环的玩家在读档时自动迁移：保留当前威胁、地点、目标和历史正文，只替换当前可执行菜单及对应场景选择记录；迁移幂等，不重复改写历史场景。

## 6. Sound Effects

- 普通选择：60–90ms 轻纸张触音，低音量，不阻塞输入。
- 领取成功：180ms 木质轻敲加柔和高音，峰值在提交确认后 40ms 内出现。
- 公共物品归属改变：240ms 两段式布料与门铃音，第二段对应界面归属更新。
- 交接/完成：320ms 温暖三音短句，不使用胜利号角。
- 冲突恢复：120ms 低沉单音后接 160ms 刷新纸张声，避免惩罚感。
- 重要对话图出现：240ms 很轻的环境过渡，不盖住语音朗读。
- 环境底噪：约 66 BPM 的稀疏节奏，混合远处自行车、门铃、雨声和楼道回响；音效总线支持静音与 `prefers-reduced-motion` 对应的弱化反馈。
